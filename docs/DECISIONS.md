| D7 | 2026-11-22 | **Reuse existing open-source tools and data before writing our own.** Custom code is limited to glue, scoring and what no maintained project covers. Each phase lists the projects it builds on. | PM direction: don't reinvent the wheel. | — |
| D8 | 2026-11-22 | **Signal quality is checked by an automated relevance judge, not by manual PM review.** A Claude Code subagent labels the sample against a written rubric (`docs/rubrics/relevance.md`); `gapfinder evaluate` validates the labels and applies the pass threshold. Labels and reports are committed under `reports/` so anyone can audit them. | PM asked for the check to be automated instead of done by hand. A fixed rubric and a separate judge agent keep it independent of the collector code. | If spot-checks show the judge disagreeing with the PM. |
| D9 | 2026-11-22 | **Embeddings use model2vec static models, not sentence-transformers/PyTorch.** BERTopic is installed with `--no-deps` and uses its model2vec backend (`potion-base-8M` for clustering, `potion-retrieval-32M` for ATT&CK shortlisting). Environment allows huggingface.co and us.aws.cdn.hf.co; downloads use plain HTTPS (`HF_HUB_DISABLE_XET=1`). | BERTopic's default install pulls in PyTorch, several GB reinstalled every session. model2vec needs only numpy. | If clustering quality limits results; a larger model can be swapped in `gapfinder/embed.py`. |
| D10 | 2026-11-22 | **Supply = GitHub repository search; threat = threat-mapper agent rating against ATT&CK.** Replaces the planned awesome-list matching and KEV similarity in the score. NVD keyword counts are shown, not scored. | Measured: the awesome-lists have no SBOM, Dependabot/Renovate or (almost) SCIM tools, and static-embedding matches against them and against KEV entries were noise (e.g. IDA Pro as the nearest tool to "CycloneDX SBOM"). | When a commercial-vendor data source is added, or Phase 4 critics find supply consistently misjudged. |
| D11 | 2026-11-22 | **Gap analysis includes the paid market.** A market researcher agent with web search maps commercial vendors, pricing, paid-market gaps, willingness to pay and bundling risk per theme (rubric `docs/rubrics/market-research.md`). Supply = 0.6 commercial crowdedness + 0.4 open-source; a new monetization component (willingness to pay, paid-market pain, bundling risk) enters the score. Weights: demand 0.30, supply gap 0.30, monetization 0.25, threat 0.15. Partly supersedes D10. | PM: "We are only looking at the unpaid market? … I'm looking to monetize this." Open-source counts alone hide markets that vendors already serve. | After Phase 4 critics review the shortlisted concepts. |
| D12 | 2026-11-22 | **Repeatable pipeline.** Agent steps are defined once in `.claude/agents/` (each points to its rubric and a validation command); `.claude/workflows/gap-analysis.js` runs Phase 2 end to end from any stage and ends with an adversarial fact-check of market claims. Agent outputs are validated with pydantic schemas (`gapfinder/schemas.py`); ranking uses scipy. | PM: "ensure we are building repeatable workflows and using whatever open source projects we need". Prompts that lived only in chat couldn't be re-run identically. | — |
| D13 | 2026-11-22 | **`cybersecurity` environment has unrestricted outbound web access** (supersedes the host list in D5). | Market researchers couldn't open vendor pricing pages (anchore.com, aws.amazon.com, socket.dev, workos.com …) and fell back on search snippets and third-party listings. Vendor sites can't be listed in advance. | If the project stops needing open web research. |
| D14 | 2026-11-23 | **Phase 2 signed off; Phase 3 shortlist = three openings** (`config/shortlist.yaml`): 1) affordable SBOM/VEX compliance for mid-size makers facing the EU CRA (themes 14 + 11), 2) buyer-side provisioning for apps without SCIM or with enterprise-locked SCIM (theme 3), 3) cheap cross-cloud workload identity for mid-market (theme 10, provisional). Chosen on the researchers' monetization verdicts rather than gap-score order. | PM: "Yes" to the recommended shortlist with CRA first. Every theme is commercially crowded; these are where researchers found paying, underserved segments. | After Phase 4 critiques. |
| D15 | 2026-11-23 | **Founder fit is part of the evaluation.** `config/founder.yaml` records the founder's profile (summarised, no name): deep hands-on security skills (MS cybersecurity; A+, Net+, Sec+, Pentest+, CySA+, Project+; CTFs, Windows, Kali, Python, automation, Windows detection engineering with WEF/Sysmon), no capital, lots of time, a few industry contacts. A `founder-fit` critic lens and the ranking use it; bootstrapping means time to first revenue, low running costs and a sales motion one technical founder can run matter more than venture-scale size. | PM review of pipeline gaps: nothing modelled who is starting the business. | When the founder's situation changes (co-founder, funding). |
| D16 | 2026-11-23 | **Rebalance demand toward buyers.** Add Server Fault (Stack Exchange API), EU public tenders (TED API v3, no key), job postings (Arbeitnow, Remotive, HN "Who is hiring") and a regulation scout agent that turns primary regulatory texts into dated obligations. Each signal records its audience (developer / practitioner / buyer); demand scoring weights buyer evidence higher. Reddit, Mastodon and Bluesky stay out (403/422 without accounts; PM declined a Reddit app). | 89% of need statements were GitHub issues and 5% had any buyer or budget language, so gaps skewed to developer plumbing. | After the iteration-2 gap report. |
| D17 | 2026-11-23 | **Open discovery before segmentation.** Collection also runs pain phrases with no segment terms (segment `open-discovery`), plus an `ai-agent-security` segment; themes from discovery can create new segments. | The four segments were chosen up front, so gaps outside them (notably AI/agent security) could not surface. | — |
| D18 | 2026-11-23 | **Backtest the method before trusting rankings.** (a) Gap finder: re-run discovery on signals dated before 2020 and measure recall of a pre-registered list of categories that later produced funded companies. (b) Critic panel: run anonymised founding-stage pitches of known successes and failures and measure whether scores separate them. Both lists are fixed in `config/backtest.yaml` before any run, and limitations (model knowledge leakage) are reported. | Thresholds and weights were chosen, not calibrated; agreement between LLM agents isn't evidence the method works. | After the first backtest results. |
| D19 | 2026-11-23 | **Stronger panel.** Add `economic-buyer`, `defensibility` and `founder-fit` lenses (nine in total). The concept writer produces three competing variants per opening (different segment, business model or channel); a variant judge picks one, grafting strong ideas from the others, before the full panel. | Nobody represented the budget owner or asked how the idea survives copying; one concept per opening meant the panel could only polish, not compare. | — |
